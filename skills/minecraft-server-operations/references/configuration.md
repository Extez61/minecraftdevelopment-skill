# Server configuration: exact scope before tuning

Skill creator: extez061

## Locate generated configuration

Read the files generated by the exact target build and its matching official documentation. Newer documentation is a lookup aid, not proof an older build accepts the same path/value. Paper's configuration layout predates some releases in this suite; do not date its introduction from the current version label.

| File / surface | Responsibility and caution |
| --- | --- |
| server.properties | Network/game basics, view/simulation distance, whitelist/authentication, RCON. Values and ranges vary by release. Do not treat it as YAML. |
| bukkit.yml | Bukkit spawn limits/timing, autosave and related settings where supported. Paper can override relevant values per world. |
| spigot.yml | Global and world-settings defaults/overrides, activation/tracking ranges and other Spigot behavior. Paper may extend/change behavior. |
| config/paper-global.yml | Server-global Paper options. Confirm exact schema and restart behavior. |
| config/paper-world-defaults.yml | Defaults inherited by Paper worlds unless overridden. |
| paper-world.yml at actual world/dimension location | Only world-specific overrides. Locate it from the running build/world layout, not a fixed historical directory guess. |
| plugins/<plugin>/... | Plugin-specific config, data and runtime caches. Check its documented reload behavior and database boundary. |
| Fabric/NeoForge config, default configs and server/world configs | Loader/mod-specific ownership, format, side and lifecycle. Do not assume every mod uses TOML or every server config has the same directory. |

Paper inheritance: an explicit world override wins over the corresponding Paper world default; omitted options inherit. Do not copy the entire defaults file into every world. Some Paper settings defer to Bukkit/Spigot; inspect their documented sentinel values individually. A `default`, `-1`, `0`, `false` or missing value is not universally equivalent. Never strip schema/version markers to make a file parse.

## Effective-value workflow

For each proposed key record: actual build, file, complete nested path, world scope, current raw value, upstream/default reference, overriding layer, effective value, units, accepted range/type and restart/reload mechanism. Inspect plugin code/settings if it deliberately changes a runtime value; do not assume a text edit controls all running state. Generated comments/defaults may differ from community guides.

Example lookup rather than a ready-made preset: view-distance in server.properties may be overridden under Spigot world-settings; simulation-distance is separate from client rendering/tracking distance. Changing a radius changes visible/ticking area and gameplay. Do not claim a squared-area estimate exactly predicts real server CPU.

Bukkit spawn-limits and ticks-per spawn attempts can be overridden by Paper world spawning settings. Paper world auto-save-interval can override Bukkit ticks-per.autosave. Verify the target version rather than adjusting a lower-priority file and reporting success.

## Settings that are not behavior-free optimizations

- Lower spawn caps, slower attempts, activation radius and AI throttling can affect farms, mobs and progression.
- Item despawn/merge, hopper transfer timing and inventory events can affect item loss, transport and protection plugins.
- Paper hopper.disable-move-event can suppress InventoryMoveItemEvent; do not enable it when preservation/protection requires that event.
- Alternate redstone implementations can change update order. They need the owner's approval and representative redstone tests.
- Smaller simulation/view/tracking distances alter gameplay/visibility. Disabling chunk/block-entity ticks or spawners removes work by removing behavior.
- Autosave removal is not a durability-safe performance fix. Do not disable watchdog, anti-cheat, auth, packet validation or backups to obtain a lower number.
- Packet/chunk rate limits need units and legitimate-client tests; a copy-pasted limit can kick players or break allowed building tools.

## Apply and validate

Read current content; create a timestamped backup outside the active config directory where practical. Avoid full-file rewrites that erase comments and unknown keys. A YAML parser proves syntax, not the Minecraft schema; reject duplicate keys/type mistakes and check server startup/effective behavior. Do not introduce a parser dependency into the server merely to edit one file. Properties escaping, repeated keys, Unicode and line endings require format-aware care.

Keep a change ledger with minimal diffs and rollback steps. Do not paste secrets from properties/global/proxy settings into reports. A restart-required change is pending until the approved restart and verification occur; a file saved successfully is not a measured runtime improvement.
